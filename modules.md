# OPTIMAX ERP — DETAILED MODULE PAGES IMPLEMENTATION SPECIFICATION

## 1. Project Objective

Extend the existing Optimax Suites website by creating three comprehensive, independent ERP module detail pages:

1. Inventory Management
2. Sales Management
3. Vendor Management

These pages must integrate naturally into the existing website and preserve its established brand identity, design system, navigation structure, typography, animations, responsiveness and overall user experience.

This is an extension of the existing website, NOT a redesign.

## 2. Mandatory Initial Audit

Before writing code:

1. Inspect the complete existing project structure.
2. Identify the framework, routing system and component architecture.
3. Examine the existing homepage and all available product/module pages.
4. Identify the current navigation structure and dropdown behavior.
5. Inspect global styles, typography, spacing, colors, buttons and reusable components.
6. Locate actual Optimax ERP screenshots, dashboard images and module-specific visual assets.
7. Identify existing animations and their implementation.
8. Examine existing CTA destinations and contact/demo workflows.

Do not introduce a new design system or unnecessary dependencies.

Reuse existing components wherever possible.

Do not modify unrelated pages or functionality.

## 3. Brand Identity

Maintain the existing Optimax visual identity.

### Brand direction

- homepage branding
- Typography: Preserve the existing website typography and must use consistently across all pages.
- Visual style: Premium Modern enterprise software, professional, minimal and confident.

### Design principles

- Strong typography hierarchy.
- Generous whitespace.
- Clear section separation.
- Purposeful use of color.
- High-quality product imagery.
- Minimal decorative elements.
- Consistent border radii and spacing.
- Subtle, purposeful animations.

Avoid:

- Excessive gradients.
- Unnecessary floating cards.
- Random decorative icons.
- Generic AI-generated dashboard illustrations.
- Repetitive feature cards.
- Excessive rounded containers.
- Overly promotional language.

The actual Optimax product interface must be the visual focus.

## 4. Navigation Architecture

Organize the new pages within the existing navigation.

### Inventory Management

Add under its appropriate inventory/product category.

Page: Inventory Management

### Commerce Management

Add:

- Sales Management
- Vendor Management

Ensure all three entries are discoverable through the existing navigation dropdown.

Preserve the current navigation design, including mobile navigation behavior.

Do not create duplicate navigation systems.

## 8. Visual Design and Product Screenshot Requirements

Actual Optimax product screenshots are the preferred visual assets.

Before creating the pages:

1. Search the existing project assets.
2. Identify screenshots belonging to each module.
3. Match each screenshot to the relevant feature.
4. Use high-quality, appropriately cropped images.
5. Preserve the original interface appearance.
6. Avoid stretching, distortion or excessive overlays.

If a specific screenshot is unavailable:

- Do not fabricate a product interface.
- Do not present an illustrative mockup as a real Optimax feature.
- Use a clean typography-led section or a simple explanatory diagram instead.
- Keep a clear distinction between actual product imagery and conceptual visuals.

Screenshots should be large enough for visitors to understand the product.

Avoid using the same dashboard image repeatedly unless it genuinely illustrates multiple capabilities.

## 9. Page Layout and User Experience

All three pages should follow a consistent visual system but have their own content and visual identity.

Recommended layout sequence:

1. Breadcrumb navigation.
2. Hero headline and product screenshot.
3. Business problem.
4. Detailed feature explanations.
5. Product interface showcases.
6. Business benefits.
7. ERP ecosystem connections.
8. Final CTA.
9. Existing website footer.

Use varied layouts throughout the page.

For example:

- Text left, screenshot right.
- Full-width product screenshot.
- Alternating feature sections.
- Split-screen feature explanations.
- Simple ecosystem diagrams.

Do not force every section into a grid of identical cards.

## 10. Animations and Interactions

Maintain the existing animation framework.

Use subtle animations:

- Hero content entrance.
- Screenshot reveal.
- Scroll-based section transitions.
- Subtle hover interactions.
- CTA transitions.

Animations must:

- Be smooth.
- Avoid unnecessary movement.
- Respect reduced-motion preferences.
- Avoid slowing down page rendering.

## 11. Responsive Requirements

All pages must work properly across:

- Desktop.
- Laptop.
- Tablet.
- Mobile.

Mobile requirements:

- Properly stacked content.
- Readable typography.
- Full-width responsive screenshots.
- No horizontal overflow.
- Accessible CTA buttons.
- Consistent spacing.
- Functional mobile navigation.

Do not simply shrink desktop layouts.

## 15. Definition of Done

The implementation is complete when:

- Three individual module detail pages exist.
- Each page has complete, module-specific content.
- Actual Optimax product screenshots are used wherever available.
- All pages preserve the existing brand identity.
- All three pages are accessible through the website navigation.
- The content communicates both business benefits and product capabilities.
- The pages work across mobile, tablet and desktop.
- All CTA buttons and internal links function correctly.
- No unsupported product capabilities have been invented.
- Existing website functionality remains intact.

Study the existing website before implementation. Preserve what already works. Extend the experience with consistency, clarity and purpose.
